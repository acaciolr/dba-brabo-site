OP · Upgrade

Upgrade guiado MOCK · runbook

Subir de versão sem susto: mesma ordem em todo motor — inventário, backup válido, réplica primeiro, primário depois, validação.

Checklist por tecnologia
  • Oracle: preupgrade.jar + fixups → GI/RDBMS em rolling (RAC um nó por vez) → datapatch → valida dba_registry_sqlpatch.
  • MySQL: checa mysqlsh util.checkForServerUpgrade() → réplica primeiro → mysql_upgrade automático no restart 8.x.
  • SQL Server: Upgrade Advisor → passivo do AG primeiro → failover → valida @@VERSION e jobs.
  • PostgreSQL: pg_upgrade --check → standby → promove → valida extensões.
  • MongoDB: setFeatureCompatibilityVersion por etapa → secondaries → stepdown do primary.
Validação

Versão nova respondendo + app conectando + backup pós-upgrade testado. Rollback = restore do backup prévio (por isso ele vem antes).

OP · Backup

Backup que presta MOCK · runbook

Backup não testado é promessa. Todo backup desta plataforma nasce com verificação e retenção declaradas.

Checklist por tecnologia
  • Oracle: RMAN BACKUP DATABASE PLUS ARCHIVELOG + VALIDATE + catalog.
  • MySQL: XtraBackup full semanal + incremental diário + --prepare de teste.
  • SQL Server: FULL + DIFF + LOG com CHECKSUM + RESTORE VERIFYONLY.
  • PostgreSQL: pg_basebackup + WAL archiving + restore de teste.
  • MongoDB: mongodump --oplog ou snapshot de filesystem com fsyncLock.
OP · Restore

Restore e PITR MOCK · runbook

Restaurar é o único teste que importa. Ensaiado fora de incidente, documentado com tempo medido (RTO real).

Checklist por tecnologia
  • Oracle: RMAN RESTORE + RECOVER UNTIL TIME → OPEN RESETLOGS → valida contagem de objetos.
  • MySQL: full + incrementais + binlog até o timestamp (mysqlbinlog --stop-datetime).
  • SQL Server: FULL + último DIFF + cadeia de LOG com STOPAT + RECOVERY.
  • PostgreSQL: base + WAL até o LSN/tempo (recovery_target_time).
  • MongoDB: restore + oplog replay até o timestamp.
OP · Migration

Migração entre motores e versões MOCK · runbook

Copiar dado é fácil; copiar sem perder e sem parar é o trabalho: replicação como ponte + cutover ensaiado.

Roteiro padrão
  1. Inventário: objetos, volumes, charset, dependências de app.
  2. Carga inicial (dump/snapshot) + replicação contínua (GoldenGate, DMS, copyInstance).
  3. Validação: contagem + checksum por tabela nos dois lados.
  4. Cutover em janela: congela escrita → drena lag → aponta app → monitora.
  5. Rollback pronto: origem intacta até o aceite formal.
OP · Security

Hardening e auditoria MOCK · runbook

Menor privilégio, criptografia e trilha — o trio que sobrevive a auditoria.

Checklist por tecnologia
  • Oracle: profiles + roles mínimas, TDE tablespace, Unified Audit, Database Vault onde couber.
  • MySQL: remove anônimos/test, caching_sha2_password, TLS obrigatório, audit plugin, TDE.
  • SQL Server: TDE + backup criptografado, Row-Level Security, SQL Audit, sem sa no app.
  • PostgreSQL: pg_hba.conf restrito, SCRAM, RLS, pgaudit, SSL.
  • MongoDB: keyfile/x.509 entre membros, RBAC por role, criptografia at-rest, auditoria.
OP · Performance

Diagnóstico por evidência MOCK · runbook

Medir antes, mudar uma coisa, medir depois. Palpite não entra no change.

Roteiro padrão
  1. Onde o tempo vai: waits/eventos (AWR/ASH, Query Store, Performance Schema, pg_stat, profiler).
  2. Plano real vs estimado (EXPLAIN ANALYZE e equivalentes).
  3. Estatísticas atualizadas antes de mexer em índice.
  4. Uma mudança por vez, com baseline gravado.
OP · Observability

Métricas, logs e alertas MOCK · runbook

O que vale alerta: replicação parada, espaço, backup envelhecido, erro recorrente. Resto é dashboard.

Três pilares por VM
  • Métricas: uptime, conexões/sessões, lag, espaço, hit ratio — coleta periódica, seuil com hysteresis.
  • Logs: erro do motor centralizado, rotação declarada, busca por janela de incidente.
  • Alertas: severidade (info/warn/crit), dono, runbook linkado — alerta sem ação documentada é ruído.
